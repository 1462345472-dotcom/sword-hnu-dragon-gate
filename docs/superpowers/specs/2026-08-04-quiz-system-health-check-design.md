**日期**: 2026-08-04
**主题**: 对29章题库系统进行代码/数据/构建/运行时四维度健康检查，加固基础设施以支撑后续22章导入
**状态**: 已确认

---

## 1. 背景与目标

### 1.1 现状

湖南大学考研题库系统已导入 **29 章**（生物化学 1-14 + 细胞生物学 1-16），以单 HTML 文件 `湖南大学题库系统.html`（2280行）运行。剩余 **22 章**（生化 15-36）有源 PDF/DOCX 但尚未生成题目 JSON。

### 1.2 目标

在下一批大规模导入前，完成一次全维度健康检查并加固基础设施，确保：

1. **现有 29 章数据零缺陷** —— 所有 JSON 格式一致、答案正确、无重复、无遗漏
2. **代码层无隐藏债务** —— 无 XSS 漏洞、无 ES6+ 语法、无内存泄漏、无死代码
3. **构建管线防退化** —— Schema 校验 + 烟雾测试嵌入构建流程，不合格即阻断
4. **运行时行为可预测** —— 4 种题型全路径验证通过

核心原则：**稳定优先，不崩盘**。改动不破坏现有功能，构建失败必须是干净利落的 `exit 1`。

## 4. 数据层扫描

### 4.1 JSON Schema 定义

#### questions.json

| 字段 | 约束 |
|------|------|
| `id` | 必填，整数，≥1 |
| `type` | 必填，枚举 `choice` \| `truefalse` \| `multi` \| `short` |
| `question` | 必填，非空字符串 |
| `options` | `choice`/`multi` 时必填，对象，键 A/B/C/D/E，值非空字符串 |
| `answer` | `choice` → 单字母 A-D；`truefalse` → `"true"`/`"false"`（全小写）；`multi` → 多字母如 "ABC"；`short` → 非空字符串 |
| `explanation` | 必填，非空字符串 |
| `difficulty` | 必填，整数 1-3 |
| `tags` | 必填，数组（可为空） |

#### terms.json

| 字段 | 约束 |
|------|------|
| `id` | 必填，整数 ≥1 |
| `term` | 必填，非空字符串 |
| `definition` | 必填，非空字符串 |
| `chapter` | 必填，非空字符串 |

### 4.2 扫描维度

| 维度 | 检查内容 |
|------|----------|
| Schema 合规 | 字段类型、必填字段、枚举值、选项数量 |
| 答案格式 | 判断题全小写、多选题字符串、选择题单字母、简答题非空 |
| 跨章一致性 | 全局 ID 唯一性（在构建时的命名空间隔离）、章节命名统一性、题型分布统计 |
| 内容质量 | 空白/占位符题目、题干长度异常、答案与选项一致性、解析与题干重复、高度相似题目 |
| terms 兼容 | list/dict 双格式各自覆盖的章节数，确认构建脚本兼容性 |

### 4.3 特别风险点

| 风险 | 说明 |
|------|------|
| 判断题大小写 | 历史提交 354958a 修复过 `True→true`，需确认无遗漏 |
| 多选题格式 | `"ABC"` vs `["A","B","C"]`，需统一为一种 |
| 章节 ID 冲突 | 不同章节的题目 ID 可能重复，构建时 namespace 隔离需确认 |
| 细胞 vs 生化差异 | 两个科目 JSON 结构是否完全一致 |

### 4.4 产出

逐章逐题的违规清单：`章节/题ID → 违规类型 → 具体问题`，可直接用作修复工单。

## 5. 构建管线加固

### 5.1 当前流程

```
各章 questions.json + terms.json
        │
        ▼
   build_unified.py
        │
        ├── 读取 JSON → 合并 QUESTION_BANKS
        ├── 读取 src_js.txt / src_css.txt 模板
        ├── base64 编码图片
        ├── 替换占位符
        └── 输出 湖南大学题库系统.html
```

### 5.2 加固后流程

```
各章 questions.json + terms.json
        │
        ▼
   ┌─────────────────────┐
   │ ① Schema 校验器      │  ← 新增：每个文件逐个过 schema
   │   不合格 → exit 1    │    输出违规文件 + 行号
   └─────────┬───────────┘
             ▼
   ┌─────────────────────┐
   │ ② 跨章一致性校验     │  ← 新增：全局 ID 冲突、章节映射完整性
   │   不合格 → exit 1    │
   └─────────┬───────────┘
             ▼
   ┌─────────────────────┐
   │ ③ 合并 + 归一化      │  ← 现有逻辑加固
   │   terms 格式统一      │    list/dict → dict
   │   答案格式归一化       │    multi 答案统一、tf toLowerCase
   └─────────┬───────────┘
             ▼
   ┌─────────────────────┐
   │ ④ 图片处理           │  ← 现有逻辑
   └─────────┬───────────┘
             ▼
   ┌─────────────────────┐
   │ ⑤ 模板注入           │  ← 现有逻辑
   └─────────┬───────────┘
             ▼
   ┌─────────────────────────────────────┐
   │ ⑥ 烟雾测试                          │  ← 新增
   │    不合格 → exit 1                  │
   │    · 4 题型各刷 N 题不报错           │
   │    · localStorage 读写不抛异常       │
   │    · 首页模块入口统计数正确           │
   │    · 跨章节切换无 JS 报错            │
   └─────────┬───────────────────────────┘
             ▼
       输出 HTML ✅
```

### 5.3 设计决策

| 决策 | 理由 |
|------|------|
| Schema 用 Python 手写，零外部依赖 | 避免 pip install，构建脚本自包含 |
| 验证失败必须 `exit(1)` | 阻断部署，不倒退回有问题的状态 |
| 烟雾测试使用 headless browser（Puppeteer 或 Playwright） | 确认真实浏览器环境无 JS 报错 |
| 保留 `src_js.txt` / `src_css.txt` 模板分离 | 不改变已有模块化方式，只加固校验层 |
| 新增 `schema_validator.py` 独立可调用 | 后续章节可单独校验，不依赖完整构建 |
