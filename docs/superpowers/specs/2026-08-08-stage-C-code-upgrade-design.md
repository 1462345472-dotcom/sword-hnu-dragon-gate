# 阶段 C 设计:代码全方位升级(UI 完全不变)

- 日期: 2026-08-08
- 状态: 规划已与用户确认(brainstorming 流程)
- 前置: 阶段 A(生化 15-36 导入)+ 阶段 B(52 章重审/优化)完成,臻至版 51 对象/5844 题/951 术语

## 1. 目标与约束

对臻至版 HTML 做**代码层全方位升级**:性能、逻辑健壮性、数据层——**UI 完全不变**(CSS 指纹 96e3aad4f8cf0d80 全程保持)。

**硬性约束**:
- UI 零改动:只动 JS 逻辑/数据加载,不动任何样式/HTML 结构
- 保持单文件内嵌(不破坏离线可用,最稳妥)
- 每项优化:备份 → 改 → 功能验证 → 浏览器实测 → git 提交;验证失败即回滚
- 技能链:code-review / tdd / systematic-debugging / verification-before-completion

## 2. 现状基线

- 单文件 HTML ~10MB(5844 题内嵌 QUESTION_BANKS)
- JS:Academy Engine(handleClick 委托、renderQuiz/renderHome/renderTerms 等)
- 已修:多选交互 bug、COURSES 顺序
- 已知数据风格问题:部分 short 题解析与答案复述冗余

## 3. 优化项(按优先级)

### 3.1 启动解析优化(核心)
- 现状:页面加载即解析全部 10MB JSON
- 方案:题目数据懒初始化——首次只解析当前章节,切章时按需解析;QUESTION_BANKS 保持内嵌但解析延迟

### 3.2 渲染性能
- renderQuiz/renderHome 全量 innerHTML → 最小化更新范围(UI 视觉不变)
- 切题/切章渲染路径优化

### 3.3 进度存储优化
- 5844 题答案进度:分章存储 + 定期合并,降低 localStorage 读写

### 3.4 索引优化
- 名词解释过滤/章节切换:预建章节→题目映射,过滤 O(n)→O(章内)

### 3.5 逻辑健壮性
- 数据解析失败兜底(损坏时提示非白屏)
- 事件委托完整性检查
- 状态管理封装(answers/revealed/bookmarks 读写统一)

### 3.6 数据层
- 启动自检(章节对象/stats 一致性,异常报警)
- short 题解析与答案复述冗余润色(数据层,不动 UI)

### 3.7 兼容性验证
- Edge/Chrome 实测 + 手机 Safari 逻辑检查
- reduced-motion 行为验证(视觉不动,行为正确)
- localStorage 压力测试

## 4. 执行流程(每项)

```
基线测试(当前耗时) → 备份 → 改代码 → 功能验证(51 章做题全流程)
→ 浏览器实测 → git 提交 → 下一项
```
